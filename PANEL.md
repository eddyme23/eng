# Optional ENG administration panel

The panel is optional, one administrator and one VPS per installation. It reuses
the terminal account managers and their existing locks, expiry and rendering.
It does not install another VPN manager or replace the gateways on 80/443.

## Install on an existing or freshly installed ENG VPS

Use Debian 12 with ENG already installed and a working Let's Encrypt certificate
for its primary domain. The default URL uses that existing domain on **TCP 8445**.
The hostname must resolve directly to the VPS (DNS-only); a standard Cloudflare
proxy is not the intended route for this listener. No firewall rule is opened
automatically. Restrict inbound TCP 8445 to your administrator IP when possible.

```bash
cd /root/eng
git pull --ff-only origin main
bash ./panel-install.sh
```

Enter a separate panel administrator name and a password of at least 3
characters. The installer prints the URL. The administrator is not a VPN or
Linux login account. Existing accounts are visible through their account section.
Installation only starts/restarts the two panel units, not VPN services.

Options:

```bash
# Alternate existing certificate hostname and an available unprivileged port:
bash ./panel-install.sh --domain panel.example.com --port 8445
# Reset the administrator login; existing VPN accounts remain unchanged:
bash ./panel-install.sh --reset-password
# Private access over an SSH tunnel instead of a public listener:
bash ./panel-install.sh --bind 127.0.0.1
```

An alternate hostname requires its own existing certificate in
`/etc/letsencrypt/live/HOST/`. The panel installer does not create DNS records or
issue certificates. For a private listener, use a tunnel and local hostname
resolution that preserve the printed HTTPS hostname/port for certificate and
origin verification. Plain HTTP is never enabled.

## Account sections

* SSH password accounts also serve WS, SSL, BHTTP, HCR, DNSTT and SocksIP.
* UDP Custom uses the same SSH password accounts, not another duplicate store.
* Certificate accounts: create, renew, list, delete all local identities, export
  private Gen JSON and export public shared authorization. Shared authorization
  import, individual identity revocation and proxy settings remain in the CLI.
* Hysteria 1/2, ZiVPN, OpenVPN and WireGuard: create, renew, delete and list.
* VLESS, VMess, Trojan, Shadowsocks and combined Xray accounts: lifecycle and links.

For ZiVPN the account name is its password. Names in this first panel version
are limited to 1-32 lowercase letters/digits/underscore/hyphen; existing CLI
accounts with other valid protocol-specific names can still be managed there.
SSH/OpenVPN creation requires a password; other credentials are generated by the
existing managers. SSH passwords cannot be recovered from hashes after creation.
Exports include Hysteria 2 URI files, Hysteria 1/ZiVPN connection JSON, WireGuard configuration, OpenVPN UDP profile,
Xray links or private certificate JSON. Download preserves the original text;
rename OpenVPN/WireGuard profiles to `.ovpn`/`.conf` as required by the client.

The dashboard shows installed service/boot state. Missing protocol installations
produce an error from their existing manager, not an automatic installation.
No traffic quotas, billing, reseller accounts, online-user estimates, QR codes,
browser shell, service restart, backup/restore or central multi-VPS management are
included in this first version. Logs and advanced controls remain in the CLI.

## Security and maintenance

The HTTPS service runs as the dedicated `frimps-panel` non-login user. A root
helper uses a group-restricted Unix socket and verifies the connecting Linux UID.
It accepts only fixed protocol/action combinations and validated account names;
there is no shell interpolation or caller-selected executable/path/environment.
The helper remains privileged because existing account tools manage Linux users
and services. Compromise of the web account would permit the allowed account
operations, so limit network access and protect administrator credentials.

Sessions use random tokens, expire after 30 minutes and are lost on restart.
Cookies are Secure/HttpOnly/SameSite=Strict. Origin/Host and CSRF tokens are checked;
login attempts and concurrent HTTP workers are bounded. Secrets are not stored
in browser local storage or logged in HTTP access logs. Output and downloads may
contain private keys/passwords: keep them private and sign out when finished.
Only metadata (operation and protocol) is logged by the helper. No MFA yet.

systemd loads the TLS certificate/key as service credentials, without opening up
the original key's permissions. A certbot deploy hook restarts only the panel
after renewal. Inspect status/logs with:

```bash
systemctl status frimps-panel frimps-panel-helper --no-pager
journalctl -u frimps-panel -u frimps-panel-helper --no-pager -n 60
```

Re-run `panel-install.sh` after pulling panel updates. It preserves administrator
credentials, bind address and port unless explicitly changed. CLI menu refreshes
alone are not the panel update procedure. To disable the optional panel:

```bash
systemctl disable --now frimps-panel.service frimps-panel-helper.service
```

This leaves VPN accounts/services unchanged. The certificate renewal hook checks
whether the panel is running before restarting it.

## Verification

Run `python3 -m unittest discover -s tests -p panel_test.py` for protocol mappings,
input rejection, real HTTP login/session/logout/CSRF/expiry/rate-limit checks and
deployment restrictions. Tests substitute account execution to avoid altering
real VPN users. Linux systemd installation, Unix peer UID checks, certificate
renewal, actual account changes and phone browsing/reconnects need a staging VPS
before production rollout. Existing protocol-manager tests cover their own logic.
